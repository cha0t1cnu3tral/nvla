What Is The Project Right Now

This project is an NVDA codebase checkout that is being actively adapted toward a Linux port, while still preserving the existing Windows behavior and architecture where possible.

Current focus:
- Building a Linux-compatible foundation without breaking the Windows code path.
- Introducing platform abstraction so core NVDA logic can call shared interfaces instead of Windows-only modules directly.
- Starting the Linux accessibility backend using AT-SPI2 (the standard accessibility stack used on Linux desktops).

Project state right now (high-level)

The project is in early-to-mid Linux port groundwork, not in a finished Linux-usable state yet.

What is already done:
- Phase 0 groundwork/documentation is in place (dependency mapping, compatibility matrix, target distro planning, CI gate draft).
- Phase 1 platform abstraction layer (PAL) has been scaffolded and partially wired into core startup/coordination paths.
- Linux platform stubs exist for features that are not implemented yet, with explicit "not supported yet" behavior.
- Phase 2 has started with an AT-SPI2 backend scaffold, plus role/state mapping helpers and initial unit tests for mappings.

What that means in practice:
- The codebase now has a structure that can support Linux work incrementally.
- Linux support is still mostly foundational; many runtime features are not implemented yet.
- Accessibility event handling and object/text integration are the main next technical blockers.

Completed work (practical summary)

1. Linux port planning and guardrails (Phase 0)
- CI gate draft for the Linux-port branch was created.
- Target Linux distro set was documented (for expected support/testing baseline).
- Windows-only dependency map was documented (to identify what must be replaced or abstracted).
- Compatibility matrix was documented (feature availability across platforms).

2. Platform Abstraction Layer (Phase 1)
- `source/platform/` structure was added with `common`, `windows`, and `linux` areas.
- A PAL entry point/factory (`source/platform/pal.py`) was added.
- Core routing in `source/core.py` now uses PAL hooks for platform-specific behaviors (accessibility/input/session/windowing paths).
- Linux placeholder implementations were added for not-yet-supported features.

3. AT-SPI2 foundation (Phase 2 initial slice)
- Linux AT-SPI backend scaffold added (`source/platform/linux/atspi_backend.py`).
- AT-SPI role/state mapping helpers added (`source/platform/linux/atspi_mappings.py`).
- Linux accessibility adapter wired to backend lifecycle (`source/platform/linux/accessibility.py`).
- Unit tests added for role/state mapping behavior (`tests/unit/test_linuxAtspiMappings.py`).

What is still missing (important)

The Linux port is not yet functionally complete because the key behavior layer is still unfinished:
- AT-SPI event bridge logic is not fully implemented.
- AT-SPI objects are not yet fully integrated into NVDA object creation flow.
- Text navigation/review support via AT-SPI Text interfaces is not implemented.
- Input/focus infrastructure for Linux (X11/Wayland) is still future work.
- Audio/speech/braille Linux-native backends are mostly future phases.
- Windows helper/injection assumptions (`nvdaHelper`) still need Linux-native replacements or redesigns later.

Immediate next development work (what should be continued next)

Phase 2 should continue next. This is the current critical path.

1. Implement AT-SPI event bridge in `ATSPI2Backend._onAtspiEvent`
- Focus events: `object:state-changed:focused`
- Property changes: `accessible:property-change`
- Caret movement: `object:text-caret-moved`


2. Add AT-SPI object wrapper integration into NVDA object creation flow
- Use role/state mapping helpers during object construction.
- Ensure Linux accessible objects can be translated into NVDA's internal object model.

Why this matters:
- Event handling alone is not enough; NVDA also needs usable objects for navigation, focus reporting, and review.

3. Implement AT-SPI TextInfo primitives
- Start with text/caret/range primitives needed for review and navigation.
- Build a minimal version first, then expand for browse/review parity.

Why this matters:
- Text access is core to screen reader usability.

4. Add event coalescing and cache policy
- Reduce D-Bus overhead and avoid event storms.
- Coalesce repeated focus/property/caret events where appropriate.

Why this matters:
- Linux AT-SPI over D-Bus can become noisy and expensive without caching/throttling.

5. Add Linux-focused unit tests for event translation behavior
- Validate event type mapping and payload translation.
- Test edge cases (missing objects, repeated events, invalid state transitions).

Why this matters:
- This is the safest way to keep progress stable while Linux support is incomplete.

What comes after that (next phase prep)

Once the AT-SPI event bridge and object/text flow are usable, the project should move into Phase 3 preparation:
- Define Linux input adapter interfaces (X11 and Wayland).
- Implement an initial keyboard focus path for Linux sessions.
- Add fallback behavior when global hooks are unavailable (especially important on Wayland).
